# 셀러 정산 마진 시뮬레이터

커머스 주문 한 건이 고객 · 셀러 · PG · 국세청 · 플랫폼으로 어떻게 나뉘는지 계산하고,
월 단위로 포인트 비용이 손익을 어디까지 끌어내리는지 보여줍니다. 정산서 · 세금계산서도 생성합니다.

**https://kennethkarl.github.io/seller-settlement/**

## 구성

- `index.html` — 시뮬레이터 전부입니다. 빌드 도구 없는 단일 파일이고, GitHub Pages가 그대로 서빙합니다.
- `roadmap.html` — 수수료 전환 로드맵. 별도 단일 파일이고 본문에서 서로 링크합니다.
- `seller-settlement-local.zip` — 로컬 편집 키트. 압축을 풀면 `CLAUDE.md`와 로컬 서버 실행 스크립트가 들어 있습니다.

## 실제 조건 넣기

화면 기본값은 중립 예시입니다. 실제 운영 수치는 코드에 두지 않고 URL 파라미터로만 넣습니다.

```
?p=판매가&d=셀러할인&pp=포인트결제액&rvb=보유리뷰P&pr=포인트전환비율&sh=배송비&sc=배송원가
&fee=수수료율&pg=PG율(VAT 별도)&vat=부가세율&n=주문건수&rf=환불률&rv=리뷰작성률&rp=리뷰건당P
&rs=셀러부담비율&ev=플랫폼포인트적립&pd=정산지급일(익월)
```

관행·법으로 답이 정해진 항목(수수료 부과 기준 · 셀러할인의 세무 성격 · 환불 시 수수료 반환)은
토글을 빼고 하나로 고정했습니다. 그래서 `base` · `disc` · `frf` · `ur` 파라미터는 더 없습니다.

전체 설명은 zip 안 `CLAUDE.md` 6번을 보십시오.

## 고칠 때

- 회사명과 실제 운영 수치를 파일에 쓰지 마십시오. 공개 저장소입니다.
- 색은 리터럴 대신 CSS 토큰을 쓰십시오. 새 토큰은 라이트 · 다크 · `data-theme` 세 곳에 모두 정의해야 합니다.
- 계산을 고쳤다면 `CLAUDE.md` 4번의 검산 스니펫으로 항등식 3개를 확인하십시오.
